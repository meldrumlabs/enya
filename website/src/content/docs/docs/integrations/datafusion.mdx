# Apache DataFusion Integration

Enya provides comprehensive observability for Apache DataFusion, the fast, extensible query engine built in Rust. Monitor query performance, track metadata changes, and understand execution patterns across commits.

## Overview

The DataFusion integration automatically instruments your DataFusion queries and provides insights into:

- Query execution performance and bottlenecks
- Logical and physical plan optimization
- Partition pruning and predicate pushdown effectiveness
- Memory usage and data scanning patterns
- Schema evolution and metadata changes over time

## Installation

Enable the DataFusion integration when adding Enya to your project:

```sh
cargo add enya --features datafusion
```

Or add it to your `Cargo.toml`:

```toml
[dependencies]
enya = { version = "0.1", features = ["datafusion"] }
```

## Basic Usage

Instrument your DataFusion context with Enya:

```rust
use enya::Enya;
use datafusion::prelude::*;

#[tokio::main]
async fn main() -> Result<()> {
    // Initialize Enya
    let enya = Enya::new()
        .with_endpoint("http://localhost:4317")
        .build()?;

    // Create an instrumented DataFusion context
    let ctx = SessionContext::new();
    let instrumented_ctx = enya.instrument_datafusion(ctx);

    // Run queries - automatically instrumented
    let df = instrumented_ctx
        .sql("SELECT * FROM my_table WHERE value > 100")
        .await?;

    let results = df.collect().await?;

    Ok(())
}
```

## Tracked Metrics

### Query Performance

- **Execution Time**: Total query execution duration
- **Planning Time**: Time spent in logical and physical planning
- **Partition Count**: Number of partitions scanned
- **Row Count**: Records processed at each stage

### Plan Optimization

- **Predicate Pushdown**: Filters pushed down to data sources
- **Projection Pruning**: Columns eliminated from scans
- **Partition Pruning**: Partitions skipped based on predicates
- **Join Reordering**: Optimizations applied to join order

### Resource Usage

- **Memory Consumption**: Peak memory usage during execution
- **I/O Operations**: Data read from storage
- **CPU Utilization**: Processing time per operator

## Commit Tracking

Track how DataFusion query performance changes across code commits:

```rust
let enya = Enya::new()
    .with_commit_tracking(true)
    .build()?;
```

This enables:
- Performance regression detection across commits
- Query plan changes between versions
- Historical performance trends
- Automated benchmarking

## Advanced Configuration

### Custom Metrics

Define custom metrics for your DataFusion queries:

```rust
enya.datafusion()
    .track_custom_metric("cache_hit_rate", |ctx| {
        // Your custom metric logic
    })
    .build()?;
```

### Selective Instrumentation

Instrument specific queries or patterns:

```rust
enya.datafusion()
    .instrument_only(|query| {
        query.contains("expensive_table")
    })
    .build()?;
```

## Best Practices

1. **Enable in Development**: Use commit tracking during development to catch regressions early
2. **Monitor Production**: Track key queries in production for performance insights
3. **Set Baselines**: Establish performance baselines for critical queries
4. **Review Plans**: Regularly review query plans in the editor to identify optimization opportunities

## Example: Tracking Query Regression

```rust
#[tokio::main]
async fn main() -> Result<()> {
    let enya = Enya::new()
        .with_commit_tracking(true)
        .with_baseline("main")
        .build()?;

    let ctx = SessionContext::new();
    let instrumented_ctx = enya.instrument_datafusion(ctx);

    // This query will be compared against the main branch baseline
    let df = instrumented_ctx
        .sql("SELECT COUNT(*) FROM large_table")
        .await?;

    let results = df.collect().await?;

    // Check for performance regressions
    if enya.has_regression() {
        println!("Warning: Query performance degraded!");
    }

    Ok(())
}
```
